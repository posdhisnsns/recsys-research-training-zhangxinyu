## 0. 发展脉络与论文速查

### 0.1 三大时代时间线

| 时代         | 时间         | 主线                        | 代表                          |
| ---------- | ---------- | ------------------------- | --------------------------- |
| **经典时代**   | 1990s–2011 | 以「用户-物品交互矩阵」为核心，低维隐向量点积预测 | 协同过滤、矩阵分解、BPR、FM            |
| **深度学习时代** | 2016–2020  | 神经网络取代点积；分化出序列、图、多任务、多兴趣  | YouTube DNN、SASRec、LightGCN |
| **前沿时代**   | 2020–至今    | 自监督/对比学习、扩散模型、大语言模型、生成式检索 | DiffRec、TIGER、TALLRec       |

**经典时代关键节点**：1994 GroupLens（UserCF 鼻祖）→ 2001 ItemCF（亚马逊）→ 2009 BPR（隐式反馈成对排序）→ 2010 FM（特征二阶交互）→ 2011 SLiM。

**深度学习时代关键节点**：2016 YouTube DNN（工业两阶段）→ 2017 NCF（神经网络替代点积）→ 2018 SASRec（单向 Transformer 序列）→ 2019 BERT4Rec（双向 Transformer）→ 2020 LightGCN（精简图卷积）。

**前沿时代关键节点**：2021 SGL（图对比学习）→ 2023 DiffRec/DiffuRec（扩散）→ 2023 TIGER（生成式检索）→ 2023 TALLRec（大模型微调）→ 2024 LLMRec（大模型增强）。

## 1. 推荐系统全景

### 1.1 现实背景：信息过载

- 物品、内容和服务数量远超用户的主动浏览能力，用户难以逐一比较所有候选。
- **搜索引擎**：根据用户输入的查询返回相关结果，适合需求比较明确的场景。
- **推荐系统**：根据用户、物品和场景信息主动筛选候选，帮助用户降低选择成本。

### 1.2 搜索 vs 推荐

| 维度  | 搜索            | 推荐                         |
| --- | ------------- | -------------------------- |
| 起点  | 明确查询          | 历史行为、物品信息、上下文、群体行为         |
| 目的  | 响应当前表达的需求     | 发现用户尚未明确表达的兴趣              |
| 关系  | 实际产品中搜索结果可个性化 | 推荐系统也可能使用检索模块（搜索和推荐并非完全分离） |

### 1.3 个性化与长尾

- **长尾现象**（Long Tail）：少数热门物品获得大量曝光，大量长尾物品难以被用户发现。
- **个性化价值**：不同用户看到不同的候选列表，长尾内容能够与潜在兴趣用户匹配。
- **潜在风险**：
  - 热门偏置可能进一步强化；
  - 推荐结果可能造成兴趣收窄或信息茧房。

### 1.4 核心难题与经典解决方式

> 推荐系统的挑战大多源于「数据稀疏 + 反馈有偏 + 偏好动态」，每一难题都有对应的经典解法与代表论文。

| 难题 | 本质 | 经典解决方式 | 代表论文 |
| --- | --- | --- | --- |
| **数据稀疏** | 交互矩阵极稀疏（99%+ 为空） | 矩阵分解降维；图卷积聚合邻居；对比学习自监督；预训练 | MF、LightGCN、SGL |
| **冷启动**（用户/物品） | 新用户/新物品无历史交互 | 内容特征、属性、知识图谱、跨域迁移、流行度兜底 | CKE、LLMRec |
| **隐式反馈**（无显式负例） | 只有正交互，缺失≠负样本 | 负采样策略；BPR 成对排序；加权损失 | BPR |
| **选择/曝光偏差** | 只能观察曝光过物品的反馈，存在分布偏移 | 逆倾向加权 IPS；因果推断；无偏排序 | Joachims et al. |
| **长尾分布** | 少数热门霸榜，长尾难曝光 | 频率正则、解耦表示、多任务专家 | — |
| **兴趣漂移/演化** | 用户兴趣随时间变化 | 序列建模、注意力、兴趣演化网络 | DIN、DIEN |
| **信息茧房/多样性不足** | 过度聚焦已有兴趣导致内容单一 | 多样性重排、探索-利用权衡、MMR | — |
| **多任务冲突** | 点击/转化/时长等多目标互相牵制 | 多门控专家、渐进分层专家 | MMoE、PLE、ESMM |
| **嵌入坍塌** | 表示趋同、失去区分度 | 加噪去噪、负熵正则、对比损失 | DiffRec、ADARec |
| **效率与可扩展性** | 海量物品实时打分成本高 | 两阶段召回-排序、向量检索 ANN、生成式检索 | YouTube DNN、TIGER |

> 上表「经典解决方式」一列中的技术名词，逐一解释如下：

- **矩阵分解降维**：把「用户×物品」的高维稀疏交互矩阵拆成两个低维稠密矩阵（用户矩阵 × 物品矩阵），相当于把用户和物品压到同一个低维隐空间，用点积还原打分。既缓解了稀疏，又得到可计算的向量表示。
- **图卷积聚合邻居**：把用户和物品看成图上的节点，交互看成边；每个节点的表示由「自己 + 邻居节点」的信息加权聚合得到，叠多层就能捕捉「朋友的朋友」这类高阶间接关系。
- **对比学习自监督**：不靠人工标注，而是给同一样本造多个「增强视图」（裁剪、掩码、加噪），让同一对象的视图互相靠近、不同对象互相远离，从而在稀疏数据里学到有区分度的表示。
- **预训练**：先在大规模数据/通用任务上把模型训出通用表示，再迁移到下游推荐任务微调，弥补目标数据不足。
- **知识图谱**：把物品、属性、实体用「三元组（头实体-关系-尾实体）」组织成图，给推荐补充物品之间的语义关联（如「这部电影的导演是…」），帮助冷启动物品被理解。
- **跨域迁移**：借用数据丰富的「源域」学到的知识，迁移到数据稀疏的「目标域」，缓解冷启动。
- **流行度兜底**：对新用户/新物品没有历史时，退回到按全局热度推荐，作为最简单的保底方案。
- **负采样策略 / BPR 成对排序 / 加权损失**：见 §3.4 与 §10.1。
- **逆倾向加权 IPS**：给「被曝光才观察得到」的样本按其曝光概率的倒数加权，纠正选择偏差，让模型估计出「如果所有物品都被看到」时的真实偏好。
- **因果推断**：把推荐过程建模为「曝光→点击」的因果链，区分相关与因果，去除混杂因素带来的偏差。
- **无偏排序**：在排序学习里显式校正位置偏差和选择偏差，使排序指标更接近真实用户偏好。
- **频率正则**：抑制高频（热门）特征的过强影响，给长尾物品更多机会。
- **解耦表示**：把「用户偏好」拆成多个互相独立的因子（如价格敏感度、品类偏好），分开建模，避免不同兴趣互相干扰，让长尾/冷门兴趣也能被单独捕获。
- **多任务专家**：用多个「专家」子网络分担不同任务/不同兴趣，各自专注，减少互相拖累（详见 §5.8 MoE）。
- **序列建模**：把用户历史行为按时间排成序列，用能处理顺序的模型（RNN/CNN/Transformer）捕捉「先后」规律，预测下一步。
- **注意力**：让模型对历史行为里的不同物品分配不同权重，预测时自动聚焦与当前目标最相关的部分。
- **兴趣演化网络**：不仅看用户「喜欢什么」，还看兴趣「如何随时间变化」（如从电子产品转向户外），用门控+注意力动态追踪演化过程。
- **多样性重排**：在保证相关的前提下，刻意让推荐列表里的物品更差异化（不同品类/风格），避免全是同类。
- **探索-利用权衡**：在「推荐已知受欢迎的（利用）」与「尝试新的冷门物品（探索）」之间做平衡，既稳又给新物品机会。
- **MMR**：最大边际相关（Maximal Marginal Relevance），重排算法，逐次挑选「既相关、又与已选列表尽量不重复」的物品。
- **多门控专家**：多个专家共享，每个任务配一个独立的「门控」决定用哪些专家（MMoE）。
- **渐进分层专家**：把专家显式拆成「共享层 + 任务专属层」，逐层分离，缓解任务冲突（PLE）。
- **加噪去噪**：给表示加噪声再让模型学「把噪声去掉」，强制模型学到更本质、更鲁棒的模式（扩散模型核心，见 §5.4）。
- **负熵正则**：惩罚「分布过于集中」的情况，鼓励更均匀、更多样化的选择（如防止控制器只选单一深度）。
- **对比损失**：对比学习的损失函数，让正样本对拉近、负样本对推远。
- **两阶段召回-排序**：先在海量物品里快速筛出几百个候选（召回），再精细打分排序（排序），兼顾效率与精度。
- **向量检索 ANN**：近似最近邻搜索，在百万级向量里快速找到最相似的一批，不逐一遍历（如 HNSW、Faiss）。
- **生成式检索**：为物品造一个语义化 ID，让模型直接「生成」目标物品 ID，替代向量相似度检索。

## 2. 应用领域与推荐任务

### 2.1 应用领域（不同领域的数据密度、实时性、评价目标差异很大）

| 应用领域   | 推荐对象        | 常见反馈/目标       |
| ------ | ----------- | ------------- |
| 电商     | 商品、店铺、搭配    | 点击、加购、购买      |
| 内容     | 新闻、视频、音乐、播客 | 播放、停留、互动      |
| 社交与信息流 | 帖子、用户、话题    | 关注、互动、停留      |
| 广告     | 广告和创意       | 点击、转化、商业约束    |
| 位置与服务  | POI、餐饮、路线   | 到店、预订、时空相关性   |
| 知识与科研  | 论文、课程、知识点   | 相关性、发现价值、学习效果 |

### 2.2 推荐任务

| 任务       | 含义            | 典型数据   |
| -------- | ------------- | ------ |
| 评分预测     | 预测用户会给物品多少分   | 显式评分矩阵 |
| 点击/交互预测  | 预测用户是否会发生某种行为 | 隐式反馈   |
| Top-N 推荐 | 从候选物品中形成排序列表  | 隐式反馈   |
| 下一物品预测   | 根据历史行为预测下一次交互 | 时间序列   |
| 会话推荐     | 单次会话内的序列推荐    | 会话日志   |
| 组合/集合推荐  | 推荐物品组合        | 关联购买数据 |

> **任务构造原则**：同一数据集可形成不同任务；过滤规则、时间划分、样本构造需与研究问题一致。

## 3. 推荐数据与用户反馈

### 3.1 数据四要素

- **用户**：人、账号、设备或匿名会话。
- **物品**：商品、视频、音乐、论文、地点或广告。
- **交互**：浏览、点击、收藏、购买、评分、播放。
- **上下文**：时间、地点、设备、入口、当前会话。

### 3.2 常见表示形式

- 用户—物品**评分矩阵**（显式）
- 用户—物品**隐式反馈矩阵**
- 按时间排列的**行为序列**

### 3.3 显式 vs 隐式反馈

- **显式反馈**：评分、喜欢/不喜欢、明确标签。
- **隐式反馈**：曝光、点击、停留、收藏、购买、跳过。
- **反馈强度**并不等价：购买 > 浏览；点击 ≠ 真正喜欢；行为受价格、库存、场景影响。
- **基本判断**：没有交互 ≠ 明确不喜欢。

### 3.4 负采样

> **名词**：负采样（Negative Sampling）——隐式反馈下通常只有正例（发生过交互），需要从「未交互物品」中抽一批当作负例，让模型学会区分「喜欢的」和「不喜欢的」。

- 隐式反馈通常只记录发生过的行为，**没有完整标注的负例**。
- 未交互物品可能表示不喜欢，也可能表示没看到。
- 训练时常从未交互物品中采样一部分作为负样本：
  - **均匀采样**：最简单，但热门物品被采为负例概率高（可能误伤）。
  - **流行度采样**：按物品热度加权采样（缓解热门偏置）。
  - **难负样本采样**：采当前模型打分高但实际未交互的物品（hard negative，提升判别力）。
  - 采样方式是一种**建模假设**；采样结果会影响模型学习；负样本数量和采样分布需要**记录**。

## 4. 经典方法

### 4.1 流行度推荐

- **思路**：统计全体用户点击/购买/播放/评分，按整体热度形成推荐。
- **使用信息**：全局交互统计，不依赖个人历史。
- **适用场景**：新用户、缺少个性化数据、作为简单基线。
- **主要问题**：缺少个性化、强化热门偏置、压缩长尾物品曝光。

### 4.2 内容推荐

- **思路**：根据用户过去喜欢的物品建立兴趣表示，推荐内容特征相似的其他物品。
- **使用信息**：类别、标签、文本、图片等物品特征 + 用户历史喜欢的物品。
- **流程**：历史喜欢 → 提取特征（爱情、浪漫…） → 候选物品特征相似 → 排序。
- **优势**：依据直观、可利用新物品内容信息。
- **问题**：依赖物品特征质量、易重复推荐相似内容、可能兴趣收窄。

### 4.3 UserCF（基于用户的协同过滤）

> **名词**：协同过滤（Collaborative Filtering, CF）——「物以类聚，人以群分」的推荐思想：不依赖物品内容，只靠「用户-物品」交互记录，找相似用户或相似物品来做推荐。UserCF 是「找人」，ItemCF 是「找物」。

- **思路**：找到兴趣相似的用户，汇总邻居喜欢而目标用户尚未交互的物品。
- **流程**：用户—物品交互 → 相似用户选择 → 邻居行为聚合 → 候选物品推荐。
- **优势**：利用群体协同信号、方法直觉清楚。
- **问题**：交互稀疏、用户兴趣变化和冷启动、大规模近邻计算成本高。

### 4.4 ItemCF（基于物品的协同过滤）

- **思路**：根据共同交互学习物品之间的相似关系，推荐与用户过去喜欢物品相似的其他物品。
- **流程**：用户—物品交互 → 物品相似关系 → 用户历史物品 → 候选物品推荐。
- **优势**：物品关系通常较稳定、容易形成「因为喜欢 A 所以推荐 B」的可解释性。
- **问题**：新物品缺少交互、热门物品共现偏置、推荐结果可能过窄。

### 4.5 矩阵分解（MF）

> **名词**：矩阵分解（Matrix Factorization, MF）——把用户和物品都映射到一个低维「隐空间」（latent space）里的向量（**隐向量/嵌入** embedding），用两个向量的**点积**预测偏好分数。隐向量是「不可直接解释、靠训练学出来的偏好特征」。

- **思路**：将用户和物品映射到同一低维隐空间，用向量点积预测偏好。
- **使用信息**：用户—物品评分矩阵或隐式反馈矩阵。
- **优势**：表示能力强、可与深度方法结合。
- **问题**：冷启动、隐向量解释有限、表示需通过训练学习。

### 4.6 经典方法对照

| 方法     | 推荐依据  | 适用入口      | 典型问题     |
| ------ | ----- | --------- | -------- |
| 流行度    | 全局热度  | 新用户、简单基线  | 热门偏置     |
| 内容推荐   | 内容相似  | 有物品特征、新物品 | 兴趣收窄     |
| UserCF | 相似用户  | 群体兴趣可迁移   | 稀疏与用户冷启动 |
| ItemCF | 相似物品  | 物品关系较稳定   | 新物品冷启动   |
| 矩阵分解   | 隐向量匹配 | 交互规模较大    | 冷启动与解释有限 |

## 5. 现代方法

> 多种方法可同时具备多个方向标签。建模对象与机制可以组合（如频域序列推荐、多模态图推荐、大模型增强的推荐）。

### 5.1 序列推荐

> **名词**：序列推荐（Sequential Recommendation）——把用户的历史交互按时间排成一条「序列」，让模型学习「看了 A 之后可能看 B」的时序规律，预测下一次交互。

| 模型 | 骨干 | 核心机制 | 论文 |
| --- | --- | --- | --- |
| GRU4Rec | RNN | 会话内依赖 | https://arxiv.org/abs/1511.06939 |
| Caser | CNN | 局部模式 | https://arxiv.org/abs/1711.09125 |
| SASRec | Transformer（单向） | 自注意力 + 因果掩码 | https://arxiv.org/abs/1808.09781 |
| BERT4Rec | Transformer（双向） | 完形填空式预训练 | https://arxiv.org/abs/1904.06690 |
| DIN | Attention | 目标相关历史加权 | https://arxiv.org/abs/1706.06978 |
| DIEN | GRU + Attention | 兴趣演化 | https://arxiv.org/abs/1809.03672 |

> **本小节机制名词**：
> - **RNN**（循环神经网络）：按时间步逐个读序列，用一个「记忆状态」把前面看到的信息带到现在，擅长建模先后依赖。
> - **CNN**（卷积神经网络）：用一个小窗口在序列上滑动，捕捉相邻几个物品之间的局部模式。
> - **单向 / 双向 Transformer**：单向只「看过去」（当前位置左边）；双向「过去未来都能看」（但要注意别让未来信息泄漏进训练）。
> - **因果掩码**：让每个位置只能关注它自己和之前的位置，模拟「从左到右」预测（见 §12）。
> - **完形填空式预训练**：像做填空一样随机遮住部分物品，让模型根据上下文猜出被遮住的是什么（BERT4Rec 的做法）。

### 5.2 图神经网络推荐

> **名词**：图神经网络（GNN）——把用户和物品当成「图」里的节点，交互当成边，让信息沿边传播、聚合邻居信息，从而捕捉「高阶连通性」（用户→物品→用户→物品的间接关系）。

- **NGCF**（SIGIR 2019, https://arxiv.org/abs/1905.08108）：在用户-物品交互图上传播嵌入。
- **LightGCN**（SIGIR 2020, https://arxiv.org/abs/2002.02126）：发现 GCN 的特征变换与非线性激活对协同过滤无益，仅保留**邻域聚合**，效果更好且更轻量。
- **SR-GNN**（AAAI 2019）：会话级图。
- **PinSage**（KDD 2018, https://arxiv.org/abs/1806.01973）：工业级大规模图推荐。

> **本小节机制名词**：
> - **邻域聚合**：节点的表示 = 把自己和邻居节点的表示按某种方式（求平均/求和）合并更新。
> - **高阶连通性**：通过「用户→物品→用户→物品」的多跳间接关系传递信息（见上方括注）。
> - **会话级图**：把一个会话里出现的物品连成一张图，捕捉会话内的转移关系。
> - **特征变换 + 非线性激活**：GCN 对聚合结果再做线性变换和 ReLU 等非线性映射；LightGCN 发现这步对协同过滤几乎无益，于是删掉只保留聚合。

### 5.3 对比学习 / 自监督推荐

> **名词**：对比学习（Contrastive Learning）——自监督的一种：给同一样本构造多个「增强视图」（如裁剪、掩码、加噪），让同一对象的不同视图在表示空间里「拉近」，不同对象「推远」。**InfoNCE** 损失是对比学习最常用的目标函数（见 §10）。

| 模型 | 核心 | 论文 |
| --- | --- | --- |
| SGL | 图结构/节点/边扰动构造增强视图 | https://arxiv.org/abs/2010.10783 |
| SimGCL | 去复杂增强，直接嵌入空间加噪声 | https://arxiv.org/abs/2112.08679 |
| CL4SRec | 序列裁剪/掩码/重排做对比 | https://arxiv.org/abs/2010.14395 |
| S3-Rec | 自监督预训练序列推荐 | https://arxiv.org/abs/2007.07869 |

> **本小节机制名词**：
> - **图结构/节点/边扰动**：随机删边、遮节点、加边等，给同一张图造出多个「增强视图」。
> - **序列裁剪/掩码/重排**：对序列做截断、随机遮盖、局部乱序，造出多个增强视图。

### 5.4 扩散推荐

> **名词**：扩散模型（Diffusion Model）——生成模型的一种：训练时给数据**逐步加噪**（前向过程），学习一个网络**逐步去噪**（反向过程）；使用时从纯噪声出发，一步步还原出干净样本。推荐里用它把「交互/物品表示」当作生成对象，学习更鲁棒、能注入不确定性的表示。

- **核心思路**：对交互或目标物品表示**逐步加噪**，学习**反向去噪**过程，恢复用户偏好或目标物品表示。
- **代表方法**：
  - **DiffRec**（SIGIR 2023, https://arxiv.org/abs/2304.04971）：对用户—物品交互向量进行去噪。两个扩展：L-DiffRec（潜空间压缩）、T-DiffRec（时序加权）。
  - **DiffuRec**（SIGIR 2023, https://arxiv.org/abs/2304.00686）：把物品表示建模为分布，注入不确定性。
- **常见任务**：Top-N 推荐、交互去噪、下一物品预测。
- **主要问题**：多步去噪增加训练/推理成本；对噪声过程、步数、实验设置较敏感。

> **本小节机制名词**：
> - **潜空间压缩**：先在低维隐空间里做扩散（更省计算），完成后再解码回原空间（L-DiffRec）。
> - **时序加权**：按交互时间远近给不同位置分配不同权重（T-DiffRec）。
> - **注入不确定性**：把物品表示从「一个确定的点」扩展成「一个分布」，表达物品的多面性/用户的多兴趣。

### 5.5 生成式检索

> **名词**：生成式检索（Generative Retrieval）——为每个物品构造一个**语义化离散 ID**（如语义码本），用序列到序列模型**直接生成**目标物品 ID，取代传统「向量相似度检索」。

- **核心思路**：为物品构造具有**语义的离散 ID**，根据历史物品 ID **直接生成**目标物品 ID。
- **代表方法**：
  - **TIGER**（ICLR 2023, https://arxiv.org/abs/2305.06474）：使用语义 ID 进行生成式推荐检索。
- **常见任务**：候选召回、下一物品预测。
- **主要问题**：语义 ID 和码本设计、物品目录更新、解码错误和推理效率。

> **本小节机制名词**：
> - **语义码本**：用聚类/量化把物品映射到一组离散「语义单元」，形成「物品→语义 ID」的字典。
> - **序列到序列模型**（Seq2Seq）：输入一个序列、输出另一个序列的模型（编码器-解码器 Transformer）。
> - **解码错误**：生成模型输出的 ID 可能是不存在或错误的，需后处理纠错。
> - **目录更新**：新物品加入时，原有语义 ID 体系需要重建或增量更新。

### 5.6 语言模型推荐（P5 范式）

- **核心思路**：将用户、物品、交互、评论和任务指令转换为**自然语言序列**，使用统一的**语言建模目标**处理多种推荐任务。
- **代表方法**：
  - **P5**（RecSys 2022, https://arxiv.org/abs/2203.13366）：预训练 + 个性化提示 + 预测；用于推荐列表生成、评分预测、推荐解释、评论生成。
- **主要问题**：物品 ID 与语言语义对齐、生成结果约束、不同任务的统一评价。
- **概念边界**：P5 体现的是「推荐任务的语言模型化」，不直接等同于通用对话式大模型。

> **本小节机制名词**：
> - **语言建模目标**：预测序列中下一个词（token）的训练目标。
> - **个性化提示**：把用户/物品信息写成自然语言「提示」，引导模型输出个性化结果。

### 5.7 大模型推荐（LLM × Rec）

> **名词**：大语言模型（LLM）——在海量文本上预训练的巨型 Transformer 模型（如 LLaMA、GPT 系列），具备语言理解、世界知识与跨任务泛化能力。用在推荐里通常有三条路线。

- **作为推荐器/生成器**：生成推荐、解释或对话结果。
- **作为对齐后的推荐模型**：使用推荐数据微调通用大模型，代表 **TALLRec**（RecSys 2023, https://arxiv.org/abs/2305.00447）。
- **作为知识与特征增强器**：补充物品属性、用户画像、关系信息，代表 **LLMRec**（WSDM 2024, https://arxiv.org/abs/2308.12241）。
- **主要价值**：语言理解、外部知识、跨任务表达、自然语言交互。
- **主要问题**：成本、时延、幻觉；物品落地约束；隐私和评价困难。

> **本小节机制名词**：
> - **微调**（Fine-tuning）：在预训练大模型基础上，用推荐数据继续训练，让模型适配推荐任务。
> - **幻觉**（Hallucination）：模型生成看似合理但实际不存在/错误的输出。

### 5.8 多任务 / 多目标推荐

> **名词**：多任务学习（Multi-Task Learning, MTL）——一个模型同时优化多个目标（点击、转化、时长）。**MoE（Mixture-of-Experts，混合专家）**是常用结构：多个专家子网络 + 门控路由，让不同任务自动用不同专家组合。

- **MMoE**（KDD 2018）：共享专家池 + 每任务独立门控，自动建模任务相关性。
- **ESMM**（SIGIR 2018, https://arxiv.org/abs/1804.07931）：用「点击→转化」链式结构缓解样本选择偏差。
- **PLE**（RecSys 2020）：渐进式分离共享与任务专属专家，缓解跷跷板效应。

> **本小节机制名词**：
> - **样本选择偏差**：训练样本只来自「被曝光」的物品，不能代表所有物品，导致估计有偏（ESMM 缓解）。
> - **跷跷板效应**：多任务里提升一个任务常以牺牲另一个任务为代价，此消彼长（PLE 缓解）。

### 5.9 现代方法对照

| 方向    | 建模重点       | 常见任务         | 主要问题           |
| ----- | ---------- | ------------ | -------------- |
| 对比学习  | 自监督训练信号    | 序列表征、推荐排序    | 正样本/增强可能偏离真实偏好 |
| 频域    | 序列频率成分     | 下一物品预测       | 周期不稳定、解释有限     |
| 扩散    | 生成与去噪      | Top-N、下一物品预测 | 多步推理、设置敏感      |
| 生成式检索 | 物品语义 ID 生成 | 召回、下一物品预测    | 码本、更新和解码效率     |
| 大模型推荐 | 语言知识与任务接口  | 推荐、解释、对话、增强  | 成本、幻觉、落地和评价    |

## 6. 多阶段推荐系统

### 6.1 三阶段

| 阶段     | 输入规模        | 作用             | 常用方法                     |
| ------ | ----------- | -------------- | ------------------------ |
| **召回** | 百万级 → 数百/数千 | 海量物品中快速筛选候选    | 流行度、协同过滤、向量检索、序列模型、生成式检索 |
| **排序** | 数千 → 数十/数百  | 精细预测候选相关性      | 综合用户、物品、交互、上下文特征         |
| **重排** | 数十 → 最终列表   | 多样性、规则、安全、重复控制 | 业务规则、多样性算法               |

> **重要边界**：召回、排序、重排是**系统阶段**，不是新的算法家族。同一方法可以服务一个或多个阶段。

### 6.2 论文模型 vs 真实系统

- **论文研究**：通常一个任务 + 一个模型 + 一个系统阶段。
- **真实系统**：多路召回 + 多个模型 + 规则/安全/内容治理 + 实时数据/延迟/稳定性。
- **离线与线上**：离线指标提高 ≠ 用户体验一定提高；单一模型结果 ≠ 完整系统效果。
- **阅读论文时**需判断：研究对象是什么、系统位置在哪、能否工程化落地。

## 7. 推荐系统合规

> 这是上线前必须考虑的问题，论文中往往被忽略。

### 7.1 合规基础

- 在具有合法处理依据和明确目的的前提下使用必要数据。
- 清晰告知个性化推荐的基本情况。
- 提供不针对个人特征的选项或便捷关闭方式。
- 允许用户选择、修改或删除用于推荐的个人标签。

### 7.2 高风险或禁止做法

- 过度收集、暗中追踪、超出原目的使用或非法共享个人信息。
- 根据用户画像实行不合理差别定价或其他差别交易条件。
- 诱导沉迷、过度消费；向未成年人推送有害内容。
- 操纵榜单、热搜和检索结果；制造虚假点赞、评论或账号。
- 推荐违法信息；利用算法规避监管；实施不正当竞争。

### 7.3 上线检查清单

- 自动化决策是否透明、公平、公正。
- 用户能否拒绝、关闭、申诉并要求必要说明。
- 是否处理敏感个人信息或未成年人个人信息。
- 是否完成必要的影响评估、安全管理、备案或安全评估。

> **法规依据**：《个人信息保护法》《互联网信息服务算法推荐管理规定》《电子商务法》。本页不替代具体法律意见。

## 8. 实验范式与公平比较

> 模型只是实验链条中的一个环节，数据、样本和比较条件同样影响结论可信度。

### 8.1 推荐实验流程

```
明确任务 → 选择数据 → 数据划分 → 构造样本 → 选择基线 → 公平比较 → 统一评价 → 训练模型 → 边界结论
```

### 8.2 数据划分

- 训练集：学习模型参数。
- 验证集：模型选择和参数调整。
- 测试集：最终评价。
- **比较要求**：使用相同的数据版本、预处理和划分；同名数据集经不同处理会形成不同实验问题。

### 8.3 时间信息泄漏（重点）

| 错误做法         | 正确做法                      |
| ------------ | ------------------------- |
| 随机打散全部序列行为   | 按时间顺序划分数据                 |
| 未来点击进入训练数据   | 过去行为训练                    |
| 用未来统计量预测过去行为 | 较新行为验证，最后行为测试             |
| —            | 物品热度/全局统计、特征构造、负样本池也要避免泄漏 |

> **基本原则**：数据划分必须与真实预测场景一致。

### 8.4 负采样 vs 评价候选集

| 比较维度 | 训练负采样     | 评价候选集           |
| ---- | --------- | --------------- |
| 目的   | 构造模型学习样本  | 决定测试时从哪些物品中寻找目标 |
| 环节   | 模型训练      | 模型评价            |
| 主要影响 | 模型学到的区分边界 | 指标难度和结果可比性      |

> 全量评价和采样评价**不能直接比较**；候选集不同，同一个 Recall@K 也**不能直接比较**。

### 8.5 基线与公平比较

- **基线层次**：流行度推荐 → ItemCF → 矩阵分解 → 合适的现代推荐模型。
- **一致条件**：数据版本、预处理、划分；评价候选集和负采样口径；列表长度 K；训练预算、调参条件、指标定义。
- **不公平做法**：只选明显较弱的基线；用不合理的实现或参数；在不同实验条件下比较指标。

### 8.6 实验结论边界

- **可说明**：模型在当前数据、任务、指标和设置下表现更好。
- **不能自动推广**：
  - 一个数据集的结果 ≠ 所有应用领域；
  - 准确性提高 ≠ 多样性/效率一定提高；
  - 离线指标提高 ≠ 线上体验一定提高。
- **结论要求**：写清数据、任务、基线和实验条件；说明结果的适用范围和限制。

## 9. 评价指标

| 指标             | 主要问题                  |
| -------------- | --------------------- |
| **Recall@K**   | 相关物品中有多少被找回           |
| **HitRate@K**  | 推荐列表是否至少命中一个目标        |
| **NDCG@K**     | 命中物品是否位于列表前部（位置折扣）    |
| **RMSE / MAE** | 预测评分与真实评分相差多少（评分预测任务） |

**指标详细解释**：

- **Recall@K（召回率）**：在「该用户实际相关的所有物品」中，推荐列表前 K 个命中了多少。关注「找得全不全」。
- **HitRate@K（命中率）**：对每个用户，推荐列表前 K 个里是否**至少命中一个**目标物品（0/1），对全体用户取平均。比 Recall 更宽松。
- **NDCG@K（归一化折损累计增益）**：既看「有没有命中」，又看「命中的位置靠不靠前」——位置越靠前权重越高（位置折扣），再除以理想排序归一化到 [0,1]。
- **Precision@K（精确率）**：推荐列表前 K 个中，真正相关的占多少。关注「推荐得准不准」。
- **MRR（平均倒数排名）**：第一个命中的倒数排名的平均。衡量「第一个正确答案排多靠前」。
- **AUC**：正样本得分高于负样本的概率，衡量打分器的排序区分能力（CTR 常用）。
- **RMSE / MAE**：预测评分与真实评分的误差（评分预测任务专用）。

> 准确性之外还应关注：覆盖率、多样性、新颖性、用户满意度、效率、鲁棒性。指标必须与任务和评价候选集相对应。

## 10. 损失函数设计

> 损失函数决定了模型「学什么」。推荐系统损失可分三大类（按样本组织方式），外加各类辅助损失。

### 10.1 主损失

| 类型                | 损失                   | 公式思想                       | 适用场景       | 代表              |
| ----------------- | -------------------- | -------------------------- | ---------- | --------------- |
| **点式（Pointwise）** | MSE                  | 预测评分与真实评分的平方差              | 显式评分预测     | MF              |
|                   | BCE / 交叉熵            | 二分类（交互/不交互）                | 隐式反馈 CTR   | NCF、Wide&Deep   |
| **对式（Pairwise）**  | BPR                  | 正样本得分应高于负样本：-ln σ(ŷ⁺ − ŷ⁻) | 隐式反馈排序     | BPR             |
|                   | Hinge / Triplet      | 间隔约束                       | 度量学习       | —               |
| **列表式（Listwise）** | Softmax CE           | 目标物品在所有候选中的概率              | 序列推荐、生成式检索 | SASRec、BERT4Rec |
|                   | InfoNCE              | 对比学习式正负对区分                 | 自监督/对比     | SGL、SimGCL      |
|                   | ListNet / LambdaRank | 直接优化排序                     | 学习排序       | —               |

> **BPR 详解**：Bayesian Personalized Ranking，成对损失。核心假设是「用户对已交互物品的偏好 > 对未交互物品的偏好」，目标是让正样本得分 ŷ⁺ 尽量高于负样本得分 ŷ⁻，即最大化 σ(ŷ⁺ − ŷ⁻)。

> **InfoNCE 详解**：对比学习的目标函数。把「正样本对」当作被正确分类的一类，在「1 个正样本 + 若干负样本」里做 softmax 交叉熵，让正样本对的相似度相对负样本对尽可能大。温度系数 τ 控制分布的锐度。

### 10.2 辅助损失（正则化 / 多目标）

| 辅助损失 | 作用 | 代表 |
| --- | --- | --- |
| L2 / Weight Decay | 防过拟合 | 几乎所有模型 |
| 对比损失（InstanceCL/IntentCL） | 自监督增强表示 | S3-Rec、SGL |
| 去噪损失（噪声预测 MSE） | 训练扩散去噪网络 | DiffRec |
| 重构损失（表示逼近） | 让增强表示逼近原始表示 | MultiVAE |
| 探索损失（负熵） | 防止控制器坍缩到单一深度/模式 | ADARec |
| 簇内/簇间距离损失 | 让同类聚拢、异类分离 | 意图聚类推荐 |
| 多任务损失（加权和） | 联合优化多目标 | MMoE、PLE |

### 10.3 损失设计要点

- **正负样本配比**：BPR 通常 1 正 1 负；InfoNCE 负样本越多越难但越能区分。
- **温度系数 τ**：控制分布锐度（越小越锐利，区分度强但易不稳）。
- **损失权重**：主损失权重通常为 1，辅助损失用小权重（如 1e-4 或经搜索）。
- **屏蔽 padding**：序列损失须屏蔽填充位置，否则梯度被 padding 污染。

## 13. ADARec：自适应扩散增强序列推荐（AAAI 2026）

> ADARec 的做法是：用「逐步去噪」的过程，从一条短短的序列里重建出用户分层的意图，从而做自适应扩散增强。

### 13.1 它要解决什么问题

核心问题是**嵌入坍塌（Embedding Collapse）**：扩散模型训练时，所有样本的表示容易越学越像、失去区分度。

**三个组件**：
1. **ADC（自适应深度控制器）**：根据每条序列，自动决定加噪的强度（depth=4 还是 5），输出概率向量来控制混合权重。
2. **HDA（混合扩散增强）**：给 Transformer 中间层的表示加噪声、再编码（用的是闭式公式，一步到位，不需要单独的去噪网络）。
3. **HP-MoE（双专家混合）**：两个独立的 SASRec 专家（一个浅层 depth 4/5、一个深层 depth 9/10），融合时各占一半（没有门控）。

**辅助对比学习**：实例级（InstanceCL）+ 意图级（IntentCL）+ 距离损失（让两个专家输出对齐）。

### 13.2 论文说法 vs 代码实现

| 模块      | 论文怎么说                 | 代码实际怎么做的               | 对得上吗  |
| ------- | --------------------- | ---------------------- | ----- |
| ADC 控制器 | 用 Gumbel-Softmax 离散采样 | 普通 softmax 软混合         | 对不上   |
| HDA 扩散  | 前向加噪 + 反向去噪网络         | 只有前向闭式加噪，没有去噪网络        | 对不上   |
| HP-MoE  | 可学习门控路由               | 固定 0.5/0.5 等权平均        | 对不上   |
| 去噪损失    | 预测噪声的 MSE             | 表示重构的 MSE（让加噪表示逼近原始表示） | 对不上   |
| 自适应深度   | 0~k 连续选择              | 只有 [4,5]/[9,10] 两档加权   | 部分对得上 |
| 骨干网络    | SASRec                | SASRec                 | 对得上   |
| 噪声调度    | 线性                    | 线性 1e-4 到 0.02, T=50   | 对得上   |
| 对比学习    | 三类（实例+意图+距离）          | 完全一致                   | 对得上   |

### 13.3 数据与训练

| 阶段     | 用什么数据                       | 看什么指标              |
| ------ | --------------------------- | ------------------ |
| 训练期验证  | valid_rating_matrix（只有训练物品） | 每个专家自己的 NDCG@20    |
| 训练结束测试 | test_rating_matrix（训练+验证物品） | 融合后的 HIT@5/NDCG@5  |
| 早停     | 两个专家各一个 EarlyStopper        | patience=40，改善阈值=0 |

**容易踩的坑**：
- 早停看的是每个专家自己的 NDCG@20，**不是**融合后的 NDCG@5（两者不是一回事）。
- `--do_eval` 模式如果忘了切换评测矩阵，验证物品会留在候选池里压低指标。

### 13.4 双专家是怎么工作的

- model_e5：depth=4,5 的 SASRec（浅层专家，抓短期、细粒度意图）
- model_e10：depth=9,10 的 SASRec（深层专家，学长期、稳定偏好）
- 融合：pred_fused = (pred_e5 + pred_e10) / 2
- 两个专家各自独立训练、独立早停，都停了才结束训练。

### 13.5 扩散增强怎么做

- **加噪**：E_t = sqrt(alpha_t) * E_0 + sqrt(1-alpha_t) * 噪声，用线性噪声调度（T=50）。
- **怎么用**：加噪后的表示作为中间层输入，和原始分支并行。
- **损失**：去噪损失 = MSE(加噪表示, 原始表示)，权重 1e-4。
- 这里用了 `.detach()` 切断梯度，让去噪损失只更新主 Transformer，不反向影响控制器。

### 13.6 损失函数组成

| 损失   | 干什么             | 默认权重 |
| ---- | --------------- | ---- |
| 推荐损失 | 让正样本分数高于负样本     | 1    |
| 去噪损失 | 让加噪表示逼近原始表示     | 1e-4 |
| 探索损失 | 防止控制器只选一个深度（负熵） | 1e-4 |
| 对比损失 | 实例级 + 意图级       | 1    |
