## 1、最近学习内容

- **OOM 根因定位与修复**：Sports 重跑训练至 epoch ~189 时 numpy 分配到 host RAM 上限，崩溃于 ArrayMemoryError。定位到 `trainers.py` 双专家验证时 `train_matrix[batch_user_index].toarray()` 每批分配 (256,18359) int32 ≈ 17.9 MiB，累积 4.5h 后耗尽。修复：改为稀疏索引 `rating_pred[batch_train.nonzero()] = 0`，峰值内存降 ~22.6 MiB，等价性已用 scipy 验证。
- **Bug #1 修复**：`datasets.py` `_data_sample_rec_task` 中 `index` 未定义（NameError），在测试分支和非测试分支均触发。修复：`self.test_neg_items[user_id]`。
- **Bug #2 清理**：`trainers.py` IntentCL 分支一行 dead code（center_center_distance 算完未赋值），已删除。
- **Sports 重跑**：清理旧 PID，用 `-WindowStyle Hidden` 分离后台进程（conda python312，torch 2.11.0+cu128），成功越过崩溃点 ~189/epoch，早停于 epoch 188（patience=40），最佳 fused HIT@5=0.0427/NDCG@5=0.0283（epoch 174），与论文基本持平。
- **Beauty 早停机制分析**：通过日志解析确认——早停监控各专家 raw NDCG@20（非 fused NDCG@5），双独立 EarlyStopper，patience=40 + delta=0 使计数器几乎总被偶然微涨清零。Beauty run 实际跑到 341/400 被 kill，从未触发早停。早停逻辑与论文原版（Cxx-0/ADARec）逐行一致，保持不改。
- **Bug #5 修复**：`--do_eval` 模式 `torch.load(checkpoint_prefix)` 缺 `_e5.pt/_e10.pt` 后缀，导致 FileNotFoundError；修复后与正常训练分支一致。
- **断点续训机制实现**：`trainers.py` 新增 `save_resume_ckpt`/`load_resume_ckpt`（打包模型/优化器/早停器快照含 numpy），`main.py` 新增 `--resume` 参数；round-trip 测试通过。
- **Bug #6 定位**：do_eval 模式 `train_matrix` 未切换为 `test_rating_matrix`，导致验证物品留在候选池与测试目标竞争，NDCG 被压低（0.0266 vs 修复后 0.0392）；修复：加载权重后加 `trainer.args.train_matrix = test_rating_matrix`。

## 3、遇到的问题

- **Beauty 日志文件追加模式含多 run 残留**：进度日志 .txt 以 append 模式写入，含旧 run 内容；需按 epoch/时间戳区分 epoch 341 截断 run 与新的修复后 run。
- **OOM 问题**：初判为显存问题，实为 numpy 大数组 host RAM 累积；根因是双专家模式下验证阶段每批调用 `train_matrix[batch_user_index].toarray()` 分配 (256,18359) int32 ≈ 17.9 MiB，累积 4.5h 后 host RAM 耗尽（非显存）。
- **Bug #3（IntentCL nn.Parameter 无 `.query()`）**：未改——模型在 `training=False` 时只返回 raw，强设 training=True 会引入 dropout/随机加噪反而错；属论文↔代码语义偏差，非崩溃 bug。
- **resume snapshot 为全停状态**：`DualExpertTrainer` 两专家在旧 Beauty run 中均已 early_stop（epoch 324），加载快照后 `valid_epoch(324)` 立刻 `return True`，训练循环 no-op；想继续训练须删 `_resume.pt` + 去掉 `--resume` 从头跑。
- **早停监控指标**：监控的是各专家 raw NDCG@20（`np.array(scores_e5[-1:])` 取 4 元素指标列表末位），不是本地训练日志输出的 fused NDCG@5；两专家都停才结束训练（`if e5_stopped and e10_stopped: return True`）。
- **Beauty 代码复现与论文一致**（验证结论）：修复 `--do_eval` 的 `train_matrix` 泄漏后，Beauty fused NDCG@5=0.0392 与论文 0.0403 差 ~0.001；此前"差 ~0.015"系误引 DiffDiv 基线 NDCG@20（0.0548）当作论文 ADARec 值，并拿 NDCG@5 错比 NDCG@20，已更正。
